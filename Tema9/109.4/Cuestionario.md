# Configuracion DNS en el lado del cliente


## Ejercicios guiados 

1. ¿Qué hará el siguiente comando?

```
getent group openldap
```

Retorna la informacion del grupo de openldap, como nombreGrupo:PasswordDelGrupo:IDGrupo:usuarios


2. ¿Cuál es la mayor diferencia entre getent y las otras herramientas cubiertas, host y dig?

Getent busca informacion no solo del dns, sino que provee informacion de hosts, usuarios, grupos, etc, acudiendo a la informacion del ssitema o dependiendo de la configuracion del archivo /etc/nsswitch.conf. Mientras que las herramientas host y dig son herramientas dedicadas a resolver nombres DNS

3. ¿Qué opción de dig y host se utiliza para especificar el tipo de registro que se desea recuperar?

En ambos comandos se usa la opcion -t para especificar el tipo de registro a recuperar

```
host -t SOA

dig -t SOA
```



4. ¿Cuál de las siguientes es una entrada correcta de /etc/hosts?

| ::1 localhost | Esta es correcta|
|---------------|-|
| localhost 127.0.0.1 | No es correcta|

La primera es la correcta por que primero se especifica la direccion y despues el nombre 

La segunda no sigue el formato establecido de l archivo /etc/hosts 

[Documento /etc/hosts]("https://man7.org/linux/man-pages/man5/hosts.5.html")

5. ¿Qué opción de getent se utiliza para especificar qué fuente de datos debe utilizarse para realizar una búsqueda? 

Se utiliza la opcion -s 

ejemplo:

```
getent -s files host learning.lpi.org
```


## Ejercicios exploratorios 

1. Si usted editara el /etc/resolv.conf que aparece a continuación con un editor de texto, ¿qué es probable que ocurra?

```
# Generated by NetworkManager
nameserver 192.168.1.20
```

|||
|---|---|
|Los cambios serán sobrescritos por NetworkManager              |   Correcto|
|NetworkManager actualizará su configuración con sus cambios    |   Correcto|
|Sus cambios no afectarán al sistema                            |   Correcto|
|NetworkManager se desactivará                                  |   Incorrecto|

2. ¿Qué significa la siguiente línea en /etc/nsswitch.conf?

```
hosts: files [SUCCESS=continue] dns
```

Significa que si encuentra algun resultado en el archivo del sistema `/etc/resolv.conf`, aun asi siga buscando la resolucion del nombre en el servicio dns

3. Teniendo en cuenta el siguiente /etc/resolv.conf ¿por qué el sistema no está resolviendo los nombres a través de DNS?

```
search lpi.org
#nameserver fd00:ffff::1:53
#nameserver 10.0.1.53
```

Las lineas estan comentadas, para que funcione deberia de ser el siguiente sin #

```
search lpi.org
nameserver fd00:ffff::1:53
nameserver 10.0.1.53
```

4. ¿Qué hace el comando dig +noall +answer +question lpi.org?

Cuando hace la consulta al servicion lpi.org en la salida,

+noall limpiara las banderas de visualizacion, 
+answr imprime la seccion de replica, que hace esto por defecto,
+question Imprime la seccion de pregunta cuando la respuesta es regresada

Muestra el registro A de lpi.org y muestra solo la consulta y la respuesta 

5. ¿Cómo puede anular los valores predeterminados de dig sin especificarlos en la línea de comandos?

Creas un archivo .digrc en tu directorio personal.
